### Retrofit de PBI-001: dos bugs de instrumento encontrados y corregidos

1. **Truncamiento por presupuesto de tokens.** `Invoke-DeepSeekChat` sin
   `-DisableThinking` gasta el `max_tokens` en `reasoning_content` (razonamiento
   visible) antes de terminar la respuesta. Con `MaxTokens=8192` cortó a mitad de
   AC-04; subir a 16000 sin tocar el razonamiento cortó en el mismo punto igual.
   Confirmado con datos (`reasoning_length` y `completion_tokens` del propio
   `Invoke-DeepSeekChat`), no supuesto: con `-DisableThinking`, `reasoning_length=0`
   y la respuesta completa en 718-871 tokens. Es la segunda vez que aparece el mismo
   síntoma (regla del 23/09: parar y verificar con datos antes de un tercer intento
   a ciegas) — se verificó la causa real antes de aplicar `-DisableThinking`.
2. **Extracción de código con regex no-greedy que corta en el primer ` ``` `.**
   `Get-CodeFromMarkdown` (del módulo compartido `C:\IA\modulo-conexion-deepseek`,
   sin tocar) usa `(.*?)` no-greedy hasta el primer fence de cierre. El test de
   AC-04 necesita, por definición, un bloque de código de ejemplo embebido — su
   propio fence de apertura corta la extracción ahí. Arreglado en el wrapper propio
   de este proyecto (`tools/deepseek/Invoke-TddDeepSeek.ps1`), no en el módulo
   compartido: extracción propia desde el primer fence de apertura hasta el
   **último** ` ``` ` de toda la respuesta.

Con ambos arreglos, DeepSeek (`deepseek-v4-pro`) escribió `tests/test_sections.py`
completo (AC-01 a AC-05) desde `tools/deepseek/specs/PBI-001.md.prompt` (contrato
público de `Section`/`parse_sections`, sin ver `sections.py`), en 7,9s, costo real
USD 0. Desarrollo (esta sesión) verificó que corre en verde contra la implementación
existente sin editarlo: 98% de cobertura, un hueco real (`stack.pop()` sin ejercitar

## Canario de Sonar: bloqueado por permisos, no por el script

`tools/sonarqube/Test-QualityGateFailure.ps1` (calco de
`whatsapp-mcp/tools/sonarqube/Test-QualityGateFailure.ps1`, projectKey propio para no
compartir estado). Falló dos veces seguidas con el mismo síntoma después de un
intento de arreglo propio (agregar `projects/create` explícito antes de escanear, y
después una clave de proyecto nueva por corrida) — por regla, se paró ahí y se
consultó a Antigravity con el síntoma crudo en vez de seguir probando solo.

**Síntoma:** `POST /api/projects/create` y el escaneo (Docker, `sonar-scanner-cli`)
funcionan con el `automation-token` de la bóveda DPAPI. `POST
/api/new_code_periods/set` sobre ESE MISMO proyecto recién creado devuelve 403
`Insufficient privileges`.

**Diagnóstico de Antigravity, confirmado con datos:** `new_code_periods/set` exige
permiso `admin` sobre el proyecto puntual (o `administer` global). Crear un proyecto
sólo requiere el permiso global `provisioning`; no lo hace administrador de lo que
crea — eso depende de la Default Permission Template (casilla «Administer» para
«Project creators»). Confirmado con
`GET /api/users/current` → `permissions.global = gateadmin, profileadmin,
provisioning, scan` — **sin `administer`**. Coincide exactamente con el otro
pendiente ya anotado el 2026-09-25: el período de código nuevo de `tokmd` mismo
tampoco se pudo fijar por API por la misma razón: la Default Permission Template de
esta instancia de Sonar no le da `Administer` a quien crea el proyecto.

**No fue un bug del script ni del canario.** Fabián confirmó por qué: en el commit
`9993532` de whatsapp-mcp (27/08/2026), el mismo endpoint sí respondía contra un
proyecto recién creado con el mismo `automation-token` — la Default Permission
Template de la instancia cambió (o el grupo del token) entre esa fecha y hoy.
Fabián le otorgó `admin` al usuario `SonarQube Automation` manualmente el
2026-09-25 (acción de administrador, fuera de lo que el token podía hacer por sí
mismo). Reintentado: **`baseline=0, scanner=3, gate=ERROR` — verde**, evidencia en
`C:\IA\Data\sonarqube\reports\tokmd-negative-gate\negative-20260925T072245Z.json`.

Con el mismo permiso ya resuelto, se aprovechó para fijar también el período de
código nuevo de `tokmd` (el otro pendiente de la lista de decisiones, punto 2):
`POST /api/new_code_periods/set` con `branch=main` (ámbito correcto, lección de
whatsapp-mcp) apuntando al primer análisis publicado
(`d610dd47-a78e-41a7-85c8-bfeae897bb06`, commit `1b14a2b`). Confirmado con `show`.
`Invoke-SonarGate.ps1 -RequireGate:$true` ya puede exigir el gate real desde el
próximo análisis.
